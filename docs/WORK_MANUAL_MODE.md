# Work 手动采集契约

在当前 Work 中输入“采集 BTC 数据”，即执行一次新的采集及完整验证。执行 `python work_collect.py`，无需逐步确认。GitHub CLI 使用已有授权；不要将凭据放入仓库，也不要要求用户提供令牌。

流程：读取触发前的已提交快照；必要时等待新的五分钟边界；带唯一 request_id 调用 workflow_dispatch；等待对应运行 success；读取本次 CSV/JSON；验证历史、窗口、公式；等待原公开地址发布本次数据；从交易所 API 独立复算最近一小时；最后按当前 UTC 重新检查新鲜度和最近闭合边界。

若验收期间又闭合了新区间，最多重新触发两次以取得当前窗口。请求失败、授权失效、运行失败、公开地址未更新、指标不一致、源接口缺失，均返回 FAIL，不返回旧数据作为成功结果。输出目录保存 report.json 及本次快照，不改写已有历史。

另列北京时间生成时间、源数据延迟分钟、Actions 结果/链接、本次能否作为 LFM 2.0 现货输入。普通聊天使用接口时也必须重新计算年龄，超过 15 分钟不得形成实时信号。

手动采集保证通过验收的最新窗口。停采期间的历史缺口如实保留；不删除原有历史，也不将窗口外历史纳入当前聚合。
